# 句读 · 双语论文阅读器 v0.4.6

本机运行的实验版阅读器。选中英文，在中文译文中同步高亮对应句子或句组；点击中文也可以反向定位。翻译时保存原文编号，不通过中英文标点数量推测对应关系。

## v0.4.6：双栏间距与桌面启动

Windows 便携版完整解压后，运行 `句读.exe`；首次运行会创建桌面和开始菜单的“句读”快捷方式，以后直接双击图标。程序后台运行，不再需要保留命令行窗口。右下角托盘可打开页面、重新创建快捷方式或退出。重复启动会复用已有本机服务；从旧版升级时先结束翻译并关闭旧服务，再打开新版。论文和译文仍在原浏览器、原端口读取。

如果要移动程序文件夹，请整体移动，之后运行新位置里的 `句读.exe` 更新快捷方式。不要单独移动 exe。源码版仍可使用 Python 或 `start.cmd` 启动。启动器为未签名的本地开源程序，源码和编译脚本随包提供；无需管理员权限，也不会设置开机自动启动。

中文排版现在按 PDF 原有字距限定栏宽，减少两栏碰撞；单个粗体词不会把整段中文加粗。长译文仍可能超出原版容积，请点击打开完整阅读，或切换舒展阅读，现有译文无需重译。

## v0.4.5：全部已译后仍有英文

“已译”表示对应句组已经收到译文，不代表 PDF 的所有区域都能安全改写。旧版可能将行内公式的上标、下标当作与正文重叠的独立区域，保留整段英文；本版在生成中文版式前，将附近的小字标记与正文行合并，减少这类误判。

独立公式、旋转页或无法安全重排的区域继续保留原样，避免破坏图表和符号。中文页头会显示当前页有多少处已译内容保留原样。点击这些区域会同步定位并打开完整中文；按方向键读到对应句组也会展开，关闭专注模式后仍有效。译文来自现有论文库，不会重新调用翻译 API。要连续查看全文，可使用“舒展阅读”。

更新后保留已有论文、对应关系与译文，不需要重新导入或重新翻译。等当前批次结束后再刷新页面；刷新需要重新填写 API 密钥。

## v0.4.4：PDF 原文与高亮更清楚

普通屏幕下，PDF 改用两倍像素绘制，减少细字和公式边缘发虚；高密度屏幕按显示比例提高，最大四倍。原版、已有中文 PDF、版式预览和原页图表预览共用此绘制方式。单页画布限制约 840 万像素、单边 8192；大页、裁切页或高倍放大时会适度降低采样，控制内存，连续页面仍按需加载。

浏览器缩放或更换显示器后自动重新绘制，保持当前句子与阅读位置。黄色高亮通过颜色叠加保留黑字，专注模式减少遮白，前后文仍清楚可辨。若双栏原文适宽后字仍太小，可在原文页头选择 125% / 150% / 200%，或切换“正文”调整字号；提高绘制分辨率不会把原本很小的文字自动放大。

更新时等当前翻译批次结束，关闭旧启动窗口，再运行新版并刷新页面。原浏览器和端口可继续读取已有论文库；刷新需重新填写密钥。

## v0.4.3：读取并选择模型

在“翻译设置”先填服务地址和密钥，再点“读取模型列表”。可搜索名称、从下拉框选择，无需先填模型名。下拉框第一项可切回手动输入；服务不提供列表或读取失败时也可继续手动填写，原模型名会保留。

模型列表只在当前设置窗口使用，切换服务、接口协议或密钥会清空旧列表，关闭窗口后也会清空。程序不会自动选中或替换已有模型；选定并保存的模型名仍按原方式保存在浏览器。

读取目录不发送论文、上下文或术语，不调用模型生成内容。返回的目录可能包含当前密钥无权使用或协议不适配的模型，选择后可用“测试连接”确认；后者会调用一次简短翻译。

本版新增后端接口，更新时需先结束当前翻译，关闭旧启动窗口，再从新版文件夹运行 `start.cmd` 并刷新页面。使用原浏览器与端口可继续读取论文库，密钥需重新填写。

## v0.4.2：API 请求兼容性

请求使用真实的 `SentenceReader/0.4.2` 客户端标识。配置 OpenCode Go 时，程序还会自动附带同一论文内稳定的随机会话编号；编号在刷新后重建，不持久保存或导出。Cloudflare 1010 会明确提示请求被模型服务前的访问规则拦截。

更新本版需要重启本机服务：先停止当前翻译，等本批结束后关闭原启动窗口，再从新版文件夹启动 `start.cmd` 并刷新页面。保持原来的浏览器和端口可继续读取已有论文库；刷新后重新填写密钥。

## v0.4.1：翻译时继续逐句阅读

翻译未完成时也可以按方向键、J/K 或 Alt+上下键切换句组，点击任一侧句子，并通过页码跳转 PDF。每批译文写入保留正在阅读的句子与手动滚动位置。编辑、重译、合并拆分和文档切换仍等待本轮翻译结束；输入框内的方向键保持文字编辑行为。

从旧版更新时，先点“完成本批后停止”，等显示已暂停后再刷新页面或替换程序文件。已完成的批次仍保存在当前浏览器；刷新后需重新填写 API 密钥，并可续译未完成部分。

## v0.4：专注阅读与阅读助手

刷新旧页面后，底部可打开“完整阅读 / 对齐检查 / 解释难句 / 术语 / 图表与公式 / 写批注”。

- **专注阅读**：勾选工具栏的“专注阅读”，两侧所选句子突出，其余内容适当变淡，包括实际 PDF。按 ↓ / → / J 下一句，↑ / ← / K 上一句；也保留 Alt+↓ / Alt+↑。方向键导航会把两侧内容带到阅读窗的中间区域。输入框、弹窗和输入法组合状态下保留正常键盘行为。
- **完整译文**：页面里的“全文↗”标签已移除。专注模式下，选中版式预览放不下的句子会自动打开完整阅读区；也可点击底部“完整阅读”。跨栏续文用省略提示，点击查看完整句组。阅读区可调宽、展开大窗，Esc 收起。右侧新增“舒展阅读”：译文自然换行、连续滚动，不受原 PDF 栏高限制。图表仍可在左侧原页或图表预览中查看。
- **对齐检查与纠正**：检查未译、中文很少、异常长度、数值 / 引文遗漏及已有警告。规则提示不是语义判定。“重新配对 / 合并 / 拆分”可在最多 40 个原文单元的编辑区内调整范围、互换译文、合为句组或手动拆开。导入的中文 PDF 可重配已有片段，并保留坐标；片段不可按标点自动细分。编辑、重配、核对标记、术语统一和批注支持本次页面内最多 30 步撤销 / 重做，快捷键 Ctrl+Z / Ctrl+Shift+Z；输入框内保留浏览器自己的文字撤销。
- **结合上下文解释**：点击“解释难句 → 解释这句话”，调用你配置的模型，发送当前句、前后两句及已有译文，展示句法结构、术语含义、作者意图。每项必须带具体原文编号和逐字引文；依据错误会要求纠正一次，仍不合格则不保存。AI 解释并非事实复核；引句存在只说明依据可定位，不保证解释正确。成功结果随档案保存。
- **术语与个人词库**：正文及常见 PDF 文字层支持悬停英文术语查看全称、中文、本文含义与原句。内置 mAP 和 ablation study 的通用释义，明确与自定义的本文含义区分。可填写自己的释义、导入 / 导出专业词库。指定旧译法后，可在包含该英文术语的句组内统一替换，并撤销；后续翻译携带自定义词库。对已排版中文 PDF 的文字统一在舒展阅读中显示，原 PDF 不改写。
- **图表与公式**：点击中英文中的 Fig. / Figure / Table / Eq. / 图 / 表 / 式编号，可展开原文页与已有对应图注。关闭后保留当前句和两侧滚动位置。编号先从正文索引、再从原 PDF 文字层查找；不可靠或找不到时可手动指定页码。预览保留整个原页上下文，不猜切图表边界；不支持扫描页 OCR、跨文献引用或所有特殊公式编号。
- **双语批注与笔记**：选中任一侧后点“写批注”，批注绑定同一组原文编号，输入即自动保存。可导出 Markdown / JSON，包含原句、当前译文、原文页码和批注。合并句组后既有批注仍按原编号保留；档案导出包含笔记、本文术语、解释和修改后的对应关系。

完整阅读、纠正、笔记、词库和图表预览无需调用模型；解释和翻译仅在点击相应操作时调用你自己的服务。API 密钥仍只保存在页面内存，档案不含密钥。撤销记录不随刷新保存，已经保存的修改与笔记会保留。

## v0.3：连续滚动与稳定句子定位

- 英文和中文 PDF 都连续排列；滚轮可跨页阅读，页码显示当前可见页，也可输入页码直接跳转。页面按需渲染，远处画布会释放，保留原来的页面空间。
- **J 下一句、K 上一句**；也可用 **Alt+↓ / Alt+↑**。一个译文组包含多句原文时，切到下一组，避免重复停在同一组。输入框、编辑区、弹窗、输入法组合状态下不拦截快捷键。
- 点击按实际字符范围命中，空白处不再吸附到附近句子；拖选按字符位置判断，避免上下行文字框重叠造成误选。两侧同时保留高亮，快速切句只执行最新的定位请求。
- 跨页原文可保留同一编号与两页坐标，两段都会高亮；提取时加强了窄双栏间隙识别、跨页大写开头与断词续接。中文跨页句组继续保留完整译文，不按标点或字数猜配。
- 手动滚动不改变所选句子；点选只在需要时移动对应的阅读窗。缩放、窗口尺寸变化、编辑和档案恢复保留滚动位置。

已有档案的原文编号、译文和对应关系会保留。**旧档案已经断开的句子不会自动重分句**，以免破坏现有译文；可用“合并下一组”合为跨页句组。未翻译的 PDF 可重新导入以使用新的提取逻辑。外部映射若语义配错，仍需修正映射；这次改动不会凭几何位置重写语义对应。

## v0.2：中文论文版式与开源工具对接

直接体验：[打开保版式演示](http://127.0.0.1:8765/?demo=layout)。或者点击“导入已排版对读包 → 打开版式演示”。演示为自拟内容与预置译文，不调用 API；首句是一句英文对应两句中文，点击任一侧会同时高亮。

本版借鉴 Zotero Bilingual 和 SideBySide 的设计，将排版与坐标对应分开：

- **已有排版好的译文**：点击“导入已排版对读包”，同时选择一份包中的 PDF 和 JSON。支持 SideBySide 的英文 PDF、中文 PDF、`alignment.json`，以及 Zotero Bilingual 的双语 PDF、`.map.json`（v2–v4）。原样渲染两侧 PDF，通过已有坐标做双向点击、拖选和翻页定位。支持一对多、区域对应和两侧页码不同；Zotero 双语 PDF 会按语言方向裁切显示，英文始终在阅读器左侧。自动保存与档案导出包含两侧 PDF。
- **只导入英文 PDF**：仍可使用自己的 API 翻译。右侧“论文版式”将译文放回原段落和栏位，保留图表与公式；这是实验性版式预览，复杂排版推荐使用成熟工具生成的中文 PDF。过长文字可在独立阅读区完整查看，也可切换“舒展阅读”连续阅读全文。跨栏或跨页的句组保留为整组，不按中文标点或长度分配给英文片段。

本版**没有安装或自动运行 BabelDOC／PDF2zh，也没有自动为两份普通 PDF 生成语义映射**。可使用 Zotero Bilingual 等工具先生成译文与坐标映射，再导入。上游语义相似度只作为核对提示，不当成准确率；导入的对应关系仍需人工核对。已排版 PDF 支持核对标记和已有片段的手动重配；若需改写原 PDF 内容，应在生成工具中修改后重新导入。

研究依据、许可证与取舍见 [UPSTREAM.md](../UPSTREAM.md)。

## 启动

1. 将整个 `sentence-reader` 文件夹放在一起，双击 `start.cmd`。
2. 浏览器会自动打开本机地址，通常是 <http://127.0.0.1:8765/>。保持服务窗口运行。
3. 再次启动会优先打开已经运行的句读实例，以保留同一浏览器地址下的论文库。

Windows 便携包自带 Python；源码版需 Python 3.9 或更新版本。无需运行 pip、npm，也不需要安装额外 Python 包。请用近期版本的 Edge 或 Chrome。

不要直接双击 `index.html`，它需要本机服务转发翻译请求。关闭启动窗口或按 Ctrl+C 即可停止服务。

## 读第一篇论文

1. **导入 PDF**：支持 60 MB、250 页以内、可选择文字的 PDF。原 PDF 自动保存在浏览器中。PDF 解析、渲染和正文提取均在本机完成。
2. **粘贴网页正文**：从论文网页复制英文正文，粘贴到导入窗口；段落间保留空行。第一版通过粘贴支持网页，不直接读取网址或安装浏览器插件。
3. **检查原文**：PDF 可以切换“原版 / 正文”，先检查双栏顺序、分句和公式附近的文本。有识别错误时，选中该原文单元，点击“修正原文”。保存修正会清空该组旧译文，原 PDF 定位保留。
4. **配置翻译服务**：填写服务地址与所需密钥，点击“读取模型列表”搜索选择，或手动填写模型名，再点击“翻译未完成部分”。可以测试连接，会产生一次简短翻译请求。
5. **逐句阅读**：点击、拖选原文，另一侧对应译文组高亮。点击中文可反向定位。支持连续选择多句、上一句 / 下一句、正文字号调整、淡化其他句子、纸张 / 明亮 / 夜间外观。PDF 支持放大、连续滚动与页码跳转；中文可切换“逐句 / 论文版式”。PDF 页面的字体与图表随放大比例缩放。

首次打开的自拟示例有预置译文，不会调用 AI。示例第 4 个原文单元对应两句中文。

## 配置其他服务或本地模型

### 兼容 Chat Completions 的服务

- 协议：选择“兼容 Chat Completions 的接口”。
- 服务地址：例如服务方提供的 `https://你的服务/v1`，也可填写完整的 `https://你的服务/v1/chat/completions`。
- 模型：点击“读取模型列表”后选择，或填写服务控制台中的准确模型名称。
- 密钥：由你在本机界面填写，通过 Bearer 认证发送。无须在聊天中提供密钥。

除下述 OpenCode Go 会话头外，其他特殊认证头、自定义消息结构或与常见 Chat Completions 不同的接口尚不支持。

兼容服务通过 `GET /models` 读取目录：例如 `https://你的服务/v1` 与完整 `https://你的服务/v1/chat/completions` 都会读取 `https://你的服务/v1/models`。目录请求最多等待 25 秒。服务返回 404 / 405、不支持常见目录结构或列表为空时，使用手动输入即可；不影响已有模型配置。

### OpenCode Go

根据 [官方 Go 文档](https://opencode.ai/docs/go/#where-can-i-use-it)（2026-10-22 核对），Go 面向 OpenCode 及发送类似请求的编程助手，要求客户端标识与稳定的会话信息。论文翻译属于其他用途，补齐请求信息不保证服务或套餐接受；本项目未用真实密钥验证付费模型请求。

官方当前 DeepSeek 配置如下：

- 协议：兼容 Chat Completions。
- 完整接口地址：`https://opencode.ai/inference/go/openai/v1/chat/completions`。
- 模型：`deepseek-v4-pro` 或 `deepseek-v4.1-flash`，以服务方实时模型列表为准。不同供应商的模型别名未必通用。
- 密钥：在本机设置中填写该服务自己的密钥。

原有 `https://opencode.ai/zen/go/v1` 路径同样会附带会话头；程序不会自动改写用户填写的地址。当前文档对应的接口见 [Go Endpoints](https://opencode.ai/docs/go/#endpoints)。

“读取模型列表”会使用官方的 Go 目录 `/inference/go/v1/models`；Zen 接口使用 `/inference/v1/models`。这不改变翻译时使用的地址。

仅在目标主机恰好是 `opencode.ai` 且为 Go 接口时，后端发送 `x-opencode-session`。它是随机编号，包含在同一论文的翻译、结构纠正重试和难句解释请求中，不含论文标题、文件名、原文、密钥或设备账号。其他兼容服务及 Ollama 不会收到该会话头。

**常见错误：** `403 / Cloudflare 1010` 表示请求在模型前被访问规则拦截，切换模型或反复重试通常无效；`MissingSessionID` 表示服务未收到会话信息，应确认已重启新版后端并刷新页面。若仍受限，向服务方确认当前客户端及使用场景；这类错误不能用于判断密钥有效或模型可用。

### Ollama

- 先启动 Ollama，并准备一个能够稳定输出 JSON 的中英翻译模型。
- 协议：选择“Ollama 原生接口”。
- 服务地址：通常是 `http://127.0.0.1:11434`。
- 模型：点击“读取模型列表”选择已安装模型，或手动填写与 `ollama list` 一致的名称。目录使用本机 `/api/tags`。
- 密钥：通常留空。
- 较小的本地模型建议先选每批 4 个原文单元。

单次服务请求最多等待 180 秒；结构不合格时额外自动纠正一次，因此一批可能需要两次请求。点击“完成本批后停止”会保留当前批次结果后停止，之后可以续译未完成部分。

## 对应关系如何保存

每个原文单元有固定的 `source_id`，以及在 PDF 中的页码和文字位置。服务按这个编号返回译文组：

```json
{
  "groups": [
    {
      "source_ids": ["s000017"],
      "translation": "该模型准确率很高。不过，它需要大量计算。",
      "needs_review": false,
      "note": ""
    }
  ]
}
```

中文可以有多个句子、调整内部语序。必要时相邻多个原文单元也可对应同一译文组。每批携带相邻上下文和可选的领域 / 术语约定，避免只看孤立句子。

程序检查编号是否完整、唯一、保持原顺序，以及译文是否为空；对明显的长度异常、中文过少、合并组和模型主动报告的问题给出核对提醒。未通过检查时要求模型纠正一次；仍不合格就拒绝写入本批结果，之前成功的批次保留。

**编号通过不等于语义正确。第一版没有独立的语义复核模型，不提供准确率或置信度保证。** 普通生成结果标记为“已生成”，人工确认后才显示“已人工核对”。

可手动处理对应关系：

- **编辑译文**：可在同一个译文块中保留任意数量的中文句子。
- **合并下一组**：把相邻两个已经翻译的组及其原文编号合并。
- **按原文拆分**：将一个合并组拆为每个原文单元一组，手动填写各自对应译文，避免凭标点错误拆分。
- **重译本组**：替换所选组的译文，不重译整篇。

## 保存、导出与密钥

论文、原 PDF、译文、对应关系和当前阅读位置保存在此浏览器的 IndexedDB 中。配置地址、模型名称、术语约定和阅读外观也会在此浏览器保存。

**API 密钥仅在当前页面内存中保留，刷新后需重新输入。** 它不写入浏览器持久存储、阅读档案或服务日志。

“导出档案”会生成 `.句读.json`，包含原文、译文、对应关系；PDF 文档还包含完整原 PDF。“导入档案”可在其他浏览器恢复阅读，导入会创建一份副本。

清理浏览器站点数据会移除本地论文库。不同浏览器、不同端口和 Codex 内置浏览器拥有各自的存储空间，不能自动共享。请在更换环境或清理数据前导出档案。

只有点击翻译 / 测试 / 难句解释时，才会向你指定的服务发送相关文字、上下文和术语说明；PDF 文件本身不会上传。选择本地 Ollama 时，应用向你填写的本机地址发请求。

## 当前边界

- 不支持扫描件 OCR、图片文字识别、网页网址直接抓取或短语级精准对齐。
- 常见单双栏按布局提取；作者信息、复杂公式、表格、跨页和特殊排版仍可能识别或分句不正确。原版 PDF 的图表可以直接看，但不会自动翻译成结构化图表。
- 为避免页边竖排编号混入正文，正文提取暂只使用水平文字；旋转文字仍显示在原版 PDF 中。
- 某些模型可能稳定返回格式正确但语义不对应的译文，必须人工核对。较弱模型反复无法返回合格 JSON 时，应尝试减少批量或更换模型。
- PDF 原版定位依赖字体文字层；少数字体编码异常的文档可能仍需用正文或粘贴方式阅读。

## 文件

- `server.py`：本机服务、翻译请求、对齐结构检查。
- `alignment.mjs`：原文分段、编号、句组及档案检查。
- `pdf-reader.mjs`：PDF 提取、文字层与字符范围高亮定位。
- `pdf-document.mjs`：连续页面、按需渲染、滚动位置和跨页定位。
- `translated-pdf.mjs`：按英文原有区域显示中文的实验预览。
- `paired-import.mjs`：两种外部对读映射格式的校验与导入。
- `focus.mjs`：PDF 专注阅读遮罩。
- `reading-tools.mjs`、`reading-data.mjs`：完整阅读、纠正与撤销、难句解释、术语、图表与批注。
- `examples/`：自拟保版式演示档案，可离线打开。
- `app.mjs`、`index.html`、`styles.css`：阅读界面与浏览器保存。
- `vendor/`：固定版本 PDF.js 4.10.38 及字体，供离线解析和显示使用；许可证随附。

本程序不内置密钥、付费账号或翻译额度。
